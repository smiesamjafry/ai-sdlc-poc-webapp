# ai-sdlc-poc-webapp — Pocket Shop

A small but complete e-commerce store (storefront + admin) used as the target repository for the
[ASDLC](https://github.com/smiesamjafry/ai-sdlc) Slack-to-PR proof of concept.

- **Storefront:** see the Render static site `pocket-shop` (URL in the Render dashboard and in `docs/demo-runbook.md`)
- **API:** Render web service `pocket-shop-api` (`/healthz`)
- **PR previews:** `https://smiesamjafry.github.io/ai-sdlc-poc-webapp/pr-preview/pr-<N>/` (browse-only). Add `[render preview]` to a PR title for a full preview with its own API and database.

## Quickstart (about 3 minutes with Docker running)

```bash
npm ci
npm run setup
npm run dev
```

Then open http://localhost:5173 (admin at `#/admin`). Logins and test cards are printed by `setup` and listed in `CLAUDE.md`.

## Architecture

```
 Render static site (SPA)  ──HTTPS + Bearer──▶  pocket-shop-api (Express)  ──▶  Postgres (truth)
 GitHub Pages PR previews  ──anonymous GET───▶        │                    ──▶  Key Value / Redis (cache, rate limits)
```

See `docs/README.md` for the API reference, error codes, demo runbook and the PRD.

## Environment

| Variable | Where | Notes |
|---|---|---|
| `APP_ENV` | API | `production`, `preview`, `development`, `test`. Production rules (required secrets, no fixture passwords) key off this, never `NODE_ENV`. |
| `DATABASE_URL`, `REDIS_URL` | API | From Render (`fromDatabase` / `fromService`). Local defaults match `docker-compose.yml`. |
| `JWT_SECRET` | API | Generated by Render. Optional locally (a dev secret is used with a warning). |
| `CORS_ORIGINS` | API | Storefront origins with full access. |
| `PREVIEW_ORIGINS` | API | Origins allowed anonymous GET only (GitHub Pages previews). |
| `STOREFRONT_URL` | API | Shown at `/`. |
| `SEED_ADMIN_PASSWORD`, `SEED_STAFF_PASSWORD` | API | Required to seed or reset when `APP_ENV=production`. |
| `REDIS_PREFIX`, `SEED_SCALE`, `LOGIN_RATE_LIMIT_PER_MIN`, `CATALOG_RATE_LIMIT_PER_MIN`, `CACHE_TTL_*_S` | API | Optional tuning. |
| `VITE_API_URL`, `VITE_PREVIEW`, `VITE_BUILD_SHA` | SPA build | API base URL, browse-only preview flag, build commit for the version banner. |

## Operations

- **Deploy order:** Render deploys both services from `main` only after GitHub checks pass (`autoDeployTrigger: checksPass`). The API runs `npm run db:migrate` as its pre-deploy command, so a failing migration stops the deploy before traffic moves.
- **Rollback:** Render dashboard → service → Deploys → *Rollback* (or `git revert` and push). Migrations are additive, so the previous API version still runs against the newer schema.
- **Reset demo data:** admin → System & cache → *Reset demo data* (type `RESET`), or `npm run db:reset -- --yes` with production env vars in a Render shell.
- **Rotate the JWT secret:** change `JWT_SECRET` in Render; every session ends.
- **Cutover note:** the old static shop kept carts in `localStorage`; those are discarded on first load of the new store.
